# DATA-SCHEMA.md — LinguaFlow

> MongoDB collections (Mongoose). Enforces the `vocabularyItem → meaning → occurrence` chain from `PRD.md` — **never flatten** vocabulary into a single record.
>
> **Conventions applied across all collections:**
> - `createdAt / updatedAt` — Mongoose `timestamps: true` option (auto-managed).
> - `isDeleted: boolean` — soft-delete flag; default `false`. Hard-deletes are **never** performed on user-generated content.
> - `deletedAt: Date | null` — set when `isDeleted` flips to `true`; `null` otherwise.
> - All queries on user-owned collections MUST include `{ isDeleted: false }` unless explicitly fetching deleted records.

---

## `users`

Stores account credentials and per-user study preferences.

```ts
{
  _id: ObjectId,

  // --- Identity ---
  email: string,           // unique, lowercase, indexed
  passwordHash: string,    // bcrypt hash — never returned in responses

  // --- Profile ---
  displayName: string,     // shown in Dashboard greeting; defaults to email prefix
  avatarUrl: string | null, // optional profile picture URL

  // --- Study Settings ---
  settings: {
    dailyReviewGoal: number,     // default 20 — cards/day target
    quizDefaultCount: number,    // default 10 — questions per quiz session
    timezone: string,            // IANA tz string, e.g. "Asia/Ho_Chi_Minh"; used for dueDate boundary
  },

  // --- Auth ---
  refreshTokenHash: string | null, // bcrypt hash of last issued refresh token (rotation)

  // --- Soft Delete ---
  isDeleted: boolean,    // default false
  deletedAt: Date | null, // set on account deletion request

  // --- Timestamps (Mongoose timestamps: true) ---
  createdAt: Date,
  updatedAt: Date,
}
```

**Indexes:**
```
{ email: 1 }  unique
```

## `vocabularyItems` — the word / lemma itself

One document per unique lemma per user. Multiple meanings can share this root.

```ts
{
  _id: ObjectId,

  // --- Ownership ---
  userId: ObjectId,   // ref: users, indexed

  // --- Content ---
  lemma: string,       // normalised lowercase form, e.g. "scale"
  partOfSpeech: string | null,  // e.g. "noun" | "verb" | "adjective" — filled by AI on first lookup

  // --- Soft Delete ---
  isDeleted: boolean,    // default false — deleting a vocabularyItem cascades to its meanings + occurrences
  deletedAt: Date | null,

  // --- Timestamps ---
  createdAt: Date,
  updatedAt: Date,
}
```

**Indexes:**
```
{ userId: 1, lemma: 1 }  unique   — one lemma per user
{ userId: 1, isDeleted: 1 }       — vocabulary list queries
```

## `meanings` — one specific sense of a lemma

A lemma can have many meanings (e.g. "scale" → weighing device vs. proportion).

```ts
{
  _id: ObjectId,

  // --- Parent ---
  vocabularyItemId: ObjectId,  // ref: vocabularyItems, indexed

  // --- Ownership (denormalized for auth guard) ---
  userId: ObjectId,  // ref: users, indexed

  // --- AI-Generated Content ---
  definition: string,   // in-context explanation generated by AiModule
  example: string,      // example sentence generated by AiModule
  aiModel: string,      // AI model version used, e.g. "gemini-2.0-flash" — for auditability

  // --- Soft Delete ---
  isDeleted: boolean,    // default false
  deletedAt: Date | null,

  // --- Timestamps ---
  createdAt: Date,
  updatedAt: Date,
}
```

**Indexes:**
```
{ vocabularyItemId: 1, isDeleted: 1 }
{ userId: 1, isDeleted: 1 }
```

## `occurrences` — one capture event; holds original context + review state

A meaning can be captured multiple times in different sentences.

```ts
{
  _id: ObjectId,

  // --- Parent Chain ---
  meaningId: ObjectId,        // ref: meanings, indexed
  vocabularyItemId: ObjectId, // ref: vocabularyItems, indexed (denormalized for cascade queries)
  userId: ObjectId,           // ref: users, indexed (denormalized for fast "due" queries)

  // --- Capture Context ---
  selectedText: string,  // exact text the user highlighted
  sentence: string,      // immediate parent sentence the word appeared in
  sourceUrl: string,     // page URL where capture occurred
  sourceTitle: string | null, // <title> of the source page (captured by content script)
  capturedAt: Date,      // explicit capture timestamp (may differ from createdAt if offline-queued)

  // --- SRS Review State (SM-2) ---
  review: {
    easeFactor: number,         // default 2.5 — SM-2 E-Factor
    intervalDays: number,       // default 1
    repetitions: number,        // default 0 — successful review streak
    dueDate: Date,              // indexed — queried by ReviewModule (GET /review/due)
    lastReviewedAt: Date | null, // null until first review
    suspended: boolean,         // default false — user can pause a card without deleting it
  },

  // --- Soft Delete ---
  isDeleted: boolean,    // default false — FR-VOCAB-003: delete occurrence without destroying lemma
  deletedAt: Date | null,

  // --- Timestamps ---
  createdAt: Date,
  updatedAt: Date,
}
```

**Indexes:**
```
{ userId: 1, "review.dueDate": 1, isDeleted: 1 }  — powers GET /review/due
{ meaningId: 1, isDeleted: 1 }
{ vocabularyItemId: 1, isDeleted: 1 }
```

## `quizzes`

One document per quiz generation request. Questions are embedded (immutable snapshot at generation time).

```ts
{
  _id: ObjectId,

  // --- Ownership ---
  userId: ObjectId,   // ref: users, indexed

  // --- Config ---
  scope: 'all' | 'recent',  // vocabulary selection scope used to generate this quiz
  questionCount: number,     // actual number of questions generated

  // --- Questions (immutable snapshot) ---
  questions: [
    {
      occurrenceId: ObjectId,   // ref: occurrences (for post-quiz score → SRS update)
      questionText: string,
      options: [string, string, string, string],  // always exactly 4 (FR-QUIZ-002)
      correctIndex: number,     // 0–3
      explanation: string,      // AI-generated post-answer rationale
    }
  ],

  // --- Status ---
  status: 'pending' | 'completed' | 'abandoned',  // default "pending"
  completedAt: Date | null,   // set when status → "completed"

  // --- Soft Delete ---
  isDeleted: boolean,    // default false
  deletedAt: Date | null,

  // --- Timestamps ---
  createdAt: Date,
  updatedAt: Date,
}
```

**Indexes:**
```
{ userId: 1, isDeleted: 1, createdAt: -1 }
{ userId: 1, status: 1 }
```

## `quizResults`

One document per completed quiz submission. Linked 1-to-1 with a `quizzes` document.

```ts
{
  _id: ObjectId,

  // --- Parent ---
  quizId: ObjectId,   // ref: quizzes, unique indexed
  userId: ObjectId,   // ref: users, indexed

  // --- Answers ---
  answers: [
    {
      questionIndex: number,   // 0-based index into quizzes.questions[]
      selectedIndex: number,   // 0–3; -1 if timed-out / skipped
      correct: boolean,
      timeSpentMs: number | null,  // optional per-question timing
    }
  ],

  // --- Aggregate ---
  score: number,          // count of correct answers
  totalQuestions: number, // snapshot of question count for denormalized % calculation
  completedAt: Date,      // when the user submitted the quiz

  // --- Soft Delete ---
  isDeleted: boolean,    // default false
  deletedAt: Date | null,

  // --- Timestamps ---
  createdAt: Date,
  updatedAt: Date,
}
```

**Indexes:**
```
{ quizId: 1 }  unique
{ userId: 1, isDeleted: 1, completedAt: -1 }  — dashboard recent scores
```

## `chatSessions`

One session per conversation thread. Messages stored as an embedded array (suitable for MVP load; extract to separate collection if sessions grow very large).

```ts
{
  _id: ObjectId,

  // --- Ownership ---
  userId: ObjectId,   // ref: users, indexed

  // --- Session Meta ---
  title: string | null,  // auto-generated summary title (first user message excerpt) or null

  // --- Messages ---
  messages: [
    {
      role: 'user' | 'assistant',
      content: string,
      createdAt: Date,  // message-level timestamp
    }
  ],

  // --- Soft Delete ---
  isDeleted: boolean,    // default false
  deletedAt: Date | null,

  // --- Timestamps ---
  createdAt: Date,
  updatedAt: Date,  // bumped on every new message — orders session list
}
```

**Indexes:**
```
{ userId: 1, isDeleted: 1, updatedAt: -1 }  — session list sorted by recency
```

## `writingReviews`

One document per writing submission. Feedback is an AI snapshot (immutable after creation).

```ts
{
  _id: ObjectId,

  // --- Ownership ---
  userId: ObjectId,   // ref: users, indexed

  // --- Input ---
  originalText: string,   // text submitted by the user
  wordCount: number,      // pre-computed for Dashboard stats

  // --- AI Output ---
  feedback: string,       // overall prose feedback
  suggestions: [string],  // list of specific improvement points
  aiModel: string,        // model version used — auditability

  // --- Soft Delete ---
  isDeleted: boolean,    // default false
  deletedAt: Date | null,

  // --- Timestamps ---
  createdAt: Date,
  updatedAt: Date,
}
```

**Indexes:**
```
{ userId: 1, isDeleted: 1, createdAt: -1 }
```

## `aiCache` (architecture §7 — lookup cache, TTL auto-expiry)

Deduplicates AI calls for identical `(selectedText, contextText)` pairs.
**No `isDeleted` / soft-delete** — this is a pure technical cache, not user data.

```ts
{
  _id: ObjectId,

  // --- Cache Key ---
  hash: string,          // sha256(selectedText + "|" + contextText), unique indexed

  // --- Cached Response ---
  meaning: string,
  example: string,
  aiModel: string,       // model that produced this response — invalidate on model change if needed

  // --- TTL ---
  createdAt: Date,       // TTL index: expires after 7 days (configurable via env CACHE_TTL_DAYS)
}
```

**Indexes:**
```
{ hash: 1 }       unique
{ createdAt: 1 }  TTL index  (expireAfterSeconds: 604800)
```

## Design Rationale — Why 3 Collections for Vocabulary

A lemma (e.g. "scale") can carry **multiple meanings** ("weighing device" vs. "proportion"), and each meaning can be **captured multiple times** across different sentences (occurrences). Flattening would either:
- duplicate the AI-generated definition per capture, or
- lose the fact that two captures share the same meaning.

This 3-layer constraint is a **fixed invariant** from `PRD.md §FR-VOCAB-002` and must never be bypassed.

## Soft-Delete Cascade Policy

| Action | Effect |
|---|---|
| Delete `vocabularyItem` | Set `isDeleted = true` on item + all its `meanings` + all their `occurrences` |
| Delete `meaning` | Set `isDeleted = true` on meaning + all its `occurrences` |
| Delete `occurrence` (FR-VOCAB-003) | Set `isDeleted = true` on occurrence **only** — parent meaning and lemma are preserved |
| Delete `chatSession` | Set `isDeleted = true` on session only (messages are embedded, no cascade needed) |
| Delete `writingReview` | Set `isDeleted = true` on review only |
| Delete `quizResult` | Not permitted — quiz results are permanent learning records |
| Delete `user` account | Soft-delete user + cascade all owned documents |
